How to read the cards

The large number is the total parameter count of the representative flagship or main open checkpoint for that family. For MoE models, active-parameter counts are intentionally omitted so sizes stay visually comparable.

The flag identifies the lab’s home country. The small label at the top-right of each card gives its primary model type; capability chips below can still mark reasoning, multimodal, coding, ASR, TTS, generation, retrieval and related traits.

Source & caveat

This is a curated visualization layer built around official Hugging Face model pages and collections from major labs. It is intentionally not a literal export of every repository: small individual publishers, quantizations, mirrors and routine checkpoint variants are excluded.

Release dating can differ between repository creation, announcement, and later model-card updates. This grid uses the first public release month for the named family/release where possible.

Method & scope

The purpose of the grid is to make release velocity visually obvious. A raw Hugging Face query contains many artifacts that would inflate the visual without adding a new model family.

  • Collapsed: parameter-size siblings, base/instruct siblings, quantizations, GGUF/FP8/AWQ conversions, and routine deployment checkpoints.
  • Kept: new named generations, substantial architecture/capability releases, and major specialized families from large or institutionally significant labs.
  • Size: representative flagship total parameter count only. Active MoE parameter counts are deliberately omitted.
  • Modalities: language, image, video/world models, audio/speech, embeddings/retrieval, computer vision and 3D are included when released by a major lab.
  • Not a benchmark: card count measures release cadence, not quality, adoption, market share, or capability.
